# 创建群组 / 群模式（对话·话题）功能与交互设计分析

> 状态：**P0 已实现并完成真机流程验证**（2026-10-21）；话题模式仍为 P2
> 素材：飞书 4 张 UI 图 —— 创建群组入口页 / 群模式·话题 / 群模式·对话 / 话题群会话页 + 话题操作菜单
> 范围：创建群全流程 + 群模式（对话 / 话题）两个模式的交互与数据设计
> 不涉及：话题模式的 Rust 协议层改造（P2 单独立项）

## 1. 一句话结论

飞书把**建群**和**群形态**合并成一步：先选人（顺带选群模式），再创建；建群页不再填群名。
「话题」不是皮肤，而是一套独立的会话形态（话题卡片流 + 订阅 + 话题级操作），工程量远大于「对话」模式，
建议拆成 P0（建群 + 群模式选择）/ P1（模式持久化）/ P2（话题群本体）三批。

## 3. 交互设计详解

### 3.1 创建群组页（图1）

结构自上而下：

1. **顶部栏**：左侧 `X`（关闭＝放弃创建），居中标题「创建群组」。没有返回箭头，也没有「下一步」。
2. **搜索框**：圆角浅灰底 + 放大镜，占位「搜索联系人、部门和我管理的群组」。输入即筛选（好友 + 我的群组）。
3. **分组带「选择联系人」**：全宽浅灰底 + 次要色小字。
4. **独立白行「群模式」**：右侧显示当前值（对话 / 话题）+ 右箭头，点击进入 3.2 的群模式页。
   这是建群前唯一可改的群属性。
5. **联系人来源分组**（白底行，彩色图标 + 右箭头）：
   - 我管理的群组 / 外部联系人 / 组织内联系人。
   - 语义是「按来源批量加人」：进列表多选；选中一个群＝把该群成员整批加入。
6. **分组带「其它方式」**；**面对面建群**（橙色图标）—— 需要服务端「同码/附近」能力。
7. **底部固定条**：左「已选：N 人」（数字用主色），右「创建」按钮（主色实心、圆角矩形，不是胶囊）。

状态与边界：

| 场景 | 设计 |
|---|---|
| 已选 0 人 | 按钮保持主色（不禁用），点击给提示「请先选择联系人」 |
| 选择中 | 底栏计数实时更新；已选成员以横向头像条（带 `X`）展示在底栏上方，可单个移除 |
| 创建中 | 按钮转 loading，防重复提交 |
| 创建失败 | 保留已选与群模式，toast 错误原因 |
| 点 `X` / 物理返回且已选 > 0 | 二次确认「放弃创建群组？」 |
| 创建成功 | 直接进入该群会话，返回列表时列表已含新群 |

### 3.2 群模式页（图2 / 图3）

- **顶部栏**：返回箭头 + 居中标题「群模式」。
- **分段控件**：两枚胶囊「对话」「话题」。选中＝主色实心 + 白字；未选中＝浅灰底 + 深字。
  **没有「确定」按钮**，点选即生效，返回时把值带回创建页。
- **说明文案**随模式变化：
  - 对话：「根据发送的先后顺序展现信息内容」；
  - 话题：「发布话题，在群内开展讨论」。
- **预览图**：用真实组件拼的示意图，不是图片资源。
  - 对话：群聊头部 + 按时间顺序的消息流 + 底部输入框；
  - 话题：主题色头部（群名 + 成员数 + 分享）+ 全部/我订阅的 tabs + 话题卡片（作者/时间/正文/回复预览）+ 底部动作条。
- **默认值**：对话。建群后应能在群设置里再次切换（飞书同样支持）。

### 3.3 话题群会话页（图4）

- **头部**：主题色（可半透明）背景；左返回；「153」话题数胶囊；右侧搜索 + 「…」。
- **群信息行**：群头像 + 群名 + 成员图标 N；右侧「分享」描边按钮。
- **分段 tabs**：全部 / 我订阅的（选中＝主色文字 + 下划线，区别于建群页的胶囊分段）。
- **话题卡片**：作者头像 + 昵称 + 时间 + 「…」；正文；回复预览块（「查看更早 N 条回复」+ 最近两条「昵称：内容」）；
  底部动作条：👍 点赞 / 💬 回复 / ↗ 分享 / ➕ 订阅（图中第 4 个被菜单遮住）。
- **右下 FAB**「+」：发布新话题。
- **话题「…」菜单**（白底圆角卡片，带分组细分线）：Pin / 置顶话题 / 添加任务 / 关闭话题 / 撤回话题。
  - 注意「Pin」与「置顶话题」是两件事（前者是把话题固定到会话内，后者是置顶到会话列表），数据落地要分开，否则先去一项。
- **空态**：没有话题时提示「还没有话题，发布第一个」；「我订阅的」筛选后为空同样需要空态。

## 4. 现状对照（我们有什么 / 缺什么）

| 能力 | 现状（代码事实） | 结论 |
|---|---|---|
| 建群 API | `GroupRepository.createGroup(groupName, groupType, memberIds)`；Rust `create_group` 已支持 faceUrl/introduction/notification/ex，但 **FFI 只暴露 name/type/memberIds**，SDK 内部把 `group_type` 写死 `2`、`ex` 写死 `None` | 建群能用；要存「群模式」必须给 FFI 加参数 |
| 群信息读取 | 服务端 `ServerGroupInfo` 有 `groupType` / `ex`，但 Rust 领域 `GroupInfo` 与 Dart `Group` 都**没有**这两个字段 | 想读回群模式，需要 Rust → FFI → Freezed 三层补字段 + codegen |
| 好友 / 我的群组 / 群成员 | Provider 齐全：`friendListProvider`、`groupListProvider`、`groupMemberProvider` | 「我的好友」「我的群组」两行可以真接通 |
| 部门 / 组织架构 / 外部联系人 | 项目没有组织架构，也没有外部联系人概念 | 图1 里这两行**没有数据源**，只能砍或占位 |
| 面对面建群 | 需要服务端「附近的人 / 同码进群」 | 只能占位或砍 |
| 消息模型 | `ChatMessage` 已有 `ex`（随消息同步）；另有本地库 `MessageExtrasStore`（🔖 标记、📌 置顶已在用） | 话题的「根消息 + 回复 + 订阅」可以挂 ext / 本地库，但跨端一致性有限 |
| 话题类服务端能力 | OpenIM 无 thread / topic / subscription API | 话题只能应用层自建，是最大的一块 |
| 现有群会话页 | `chat_detail_screen` 只有一套「顶栏 + 消息流 + 输入框」布局 | 话题群需要**另一套**会话页，不要改现有详情页 |

## 5. 分期实施建议

### P0（本轮：纯 Flutter UI + 已有 SDK 能力）

1. **创建群组页按图1 重做**（`lib/ui/groups/views/create_group_screen.dart`）：
   - `X` 关闭 + 居中标题；搜索框（好友 + 我的群组实时过滤）；
   - 「群模式」行（值来自 3.2 页）；
   - 「选择联系人」分组：**我的好友**（多选页）、**我的群组**（选群＝整批拉入群成员）；
   - 「其它方式 → 面对面建群」占位提示（不做假功能）；
   - 底部「已选：N 人 + 创建」，已选成员横向头像条可单个移除；
   - 群名默认策略：后端 `groupName` 必填，用「自己 + 前两位成员昵称」拼接（超三人加「等」），建完可在群设置改名。
2. **群模式页按图2/3 实现**（新增 `lib/ui/groups/views/group_mode_screen.dart`）：胶囊分段 + 文案 + 代码绘制的两张预览图；选值回传创建页。
3. **边界处理**：0 人提示、创建中 loading、失败保留选择、关闭二次确认。
4. **创建后去向**：P0 先「返回列表 + toast」（保守），或确认 `sg_<groupId>` 会话可用后直接进群会话（需拍板）。
5. **验证**：模拟器 Flutter MCP 热重载逐屏渲染 + 连服务端真实建群一次。

### P1（群模式真持久化）

- Rust：`create_group` 增加 `ex`（或 `group_type`/`mode`）入参；`GroupInfo` 领域模型与 `server_to_group_info` 带上 `ex` / `group_type`。
- FFI：`create_group` 加参数 → `flutter_rust_bridge_codegen generate` + `scripts/check-codegen.ps1`。
- Dart：`Group` 模型补字段 → `dart run build_runner build`；`mapGroup` 映射 `ex`。
- 群设置页加「群模式」入口（对话 / 话题切换，建议仅群主可改）。

### P2（话题群本体，独立立项）

- **数据**：话题根消息（`ex` 带 `topicId` + 主题信息）+ 回复消息（`ex` 带 `topicId`）；订阅、Pin、关闭状态建议先本地库。
- **界面**：话题群会话页（图4）——主题色头部、全部/我订阅的、话题卡片流、「查看更早 N 条回复」、FAB 发布。
- **话题菜单**：Pin / 置顶话题 / 添加任务 / 关闭话题 / 撤回话题（撤回可复用消息撤回；「添加任务」需要任务系统，先占位）。
- **一致性**：只有 `ext` 能跨端同步，订阅/置顶等本地状态多端会不一致，需产品接受或服务端支持。

## 8. 创建成功闭环修复（2026-10-21）

- 现象：群创建接口返回成功，服务端也已生成 `sg_<groupID>` 会话，但客户端会话列表看不到新群，用户误以为创建失败。
- 根因：① Rust `create_group` 只更新内存群列表，没有持久化群信息、也没有落本地会话；② 创建页 `pop(Group)` 后调用方忽略了返回值，既没刷新会话，也没进入新群。
- 修复：Rust 创建群后同时 upsert `local_groups` 与 `local_conversations`（`sg_<groupID>`，最新时间取当前时间）；会话列表收到返回的 `Group` 后 `loadConversations()` 并直接进入 `sg_<groupID>`。
- 验证：真机 `flutter_drive` 全流程通过（创建群 658698100 → 自动进入群聊 → 发送文本 → @所有人 入口），见 `test_driver/group_flow_driver.dart`。
