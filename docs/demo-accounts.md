## 1. 前置条件与登录方式

1. 起服务：Docker OpenIM（端口 `10001` WebSocket / `10002` API / `10008` 认证 / `10005` MinIO）。
2. 设备侧转发：`powershell -ExecutionPolicy Bypass -File scripts\adb_reverse.ps1`
   （`ANDROID_HOME` 指向本机 SDK，如 `D:\Data\Android\Sdk`；**USB 掉线重连后必须重跑**，否则登录/上传/语音都会失败）。
3. App 登录：登录页切「验证码登录」，先点「获取验证码」，验证码固定 **`666666`**。

## 6. 运维与校验命令

### 6.1 造演示数据（会为目标账号补联系人 + 会话 + 消息）

```powershell
# 读 App 当前登录手机号 → OPENIM_DEMO_TARGET_PHONE → 跑 seed_demo
powershell -ExecutionPolicy Bypass -File rust\scripts\seed-demo.ps1
# 等价手写：
$env:OPENIM_DEMO_TARGET_PHONE = '17764008284'
cargo test --test seed_demo -- --ignored --test-threads=1 --nocapture   # 在 rust/ 下执行
```

### 6.2 手动建立双向好友（本文 §4 就是这么建的）

```powershell
# 1) 取 admin token（注意必须带 operationID 头）
$h  = @{ operationID = [guid]::NewGuid().ToString() }
$tok = (Invoke-RestMethod -Uri "http://127.0.0.1:10002/auth/get_admin_token" -Method Post -Headers $h `
        -ContentType 'application/json' -Body '{"secret":"openIM123#&9873d","userID":"imAdmin"}').data.token

# 2) 双向 import_friend（ownerUserID ← friendUserIDs）
foreach ($p in @(@('2006526104','2772835353'), @('2772835353','2006526104'))) {
  $hd = @{ token = $tok; operationID = [guid]::NewGuid().ToString() }
  Invoke-RestMethod -Uri "http://127.0.0.1:10002/friend/import_friend" -Method Post -Headers $hd `
    -ContentType 'application/json' -Body ('{"ownerUserID":"' + $p[0] + '","friendUserIDs":["' + $p[1] + '"]}')
}

# 3) 校验（friendsInfo[].friendUser.userID / nickname）
Invoke-RestMethod -Uri "http://127.0.0.1:10002/friend/get_friend_list" -Method Post -Headers $hd `
  -ContentType 'application/json' -Body '{"userID":"2006526104","pagination":{"pageNumber":1,"showNumber":200}}'
```

> 客户端拉取好友是**增量同步**：加完好友后需要重新登录（或冷启动）才会出现在「通讯录」。
> 会话列表要有消息才显示；联系人请到**「通讯录」**查看（会话内搜索框搜的是消息内容，不搜联系人）。

### 6.3 手机号 → userID / 账号与群清单

```powershell
# 手机号换 userID（chat 服务 10008，验证码固定 666666）
Invoke-RestMethod -Uri "http://127.0.0.1:10008/account/login" -Method Post -ContentType 'application/json' `
  -Body '{"phoneNumber":"17764008284","areaCode":"+86","verifyCode":"666666","platform":5}'
```

带 admin token 的查询接口（POST，body 见括号）：

- `/user/get_users`（`{"pagination":{"pageNumber":1,"showNumber":500}}`）→ 全量用户（昵称/userID）
- `/group/get_groups`（同上）→ 全部群
- `/group/get_group_member_list`（`{"groupID":"...","pagination":{...}}`）→ 群成员
- `/friend/get_friend_list`（`{"userID":"...","pagination":{...}}`）→ 某人好友（好友关系**不是对称存储**，要双向查或用 §6.2 双向 import）

## 7. 注意事项

- 服务端数据会随自动化测试持续累积（当前 1144 用户 / 81 群），账号清单以本文的「演示账号」为准，其余多为测试残留。
- 早期 seed 用过「手机号当 userID」的写法，于是出现 `2361018881`（遗留账号）与 `2006526104`（同手机号的新账号）并存；会话 id 形如 `si_2361018881_2772835353` 指的是**遗留账号**与「小萌」，不是真机账号。
- 好友关系通过 `/friend/import_friend` 建立后，两端 App 需重新登录/冷启动同步；**已登录期间新增的好友不会实时推送**。
- 本文件由实测导出，新增/删除账号或群后请同步更新。
